# Campaign Content Automation Plan & Workflow

This document details the operational workflow for converting weekly cybersecurity awareness themes into draft social media posts and quiz questions. It outlines a zero-cost manual baseline workflow alongside an optional Zapier/Make automation architecture featuring strict **Human-In-The-Loop (HITL)** safety guardrails.

---

## 1. Operational Principles & Ethical Boundaries

To prevent misinformation, hallucinated threat advice, or unintended disruption to campus communications, this workflow enforces three non-negotiable safety guardrails:

1. **Mandatory Human-In-The-Loop (HITL) Sign-Off:** No content generated by artificial intelligence or automated webhooks is ever published, broadcast, or added to production datasets without explicit, recorded review by a qualified cybersecurity analyst or campus communication coordinator.
2. **Zero Paid Software Dependencies:** The base operational workflow is fully executable using free, open-source, or local tools without requiring paid subscriptions.
3. **Fact-Checking Against Authoritative Standards:** All generated awareness advice must be validated against recognized cybersecurity frameworks (NIST SP 800-63, CISA Phishing Guidance, CERT-In Advisories).

---

## 2. Zero-Cost Manual Workflow (Baseline)

The manual workflow is the primary operational procedure for collegiate security clubs, IT helpdesks, and student awareness coordinators.

```
┌─────────────────────┐
│ 1. Weekly Threat    │  Select theme from campus incident trends or CISA advisories
│    Topic Selection  │  (e.g., Week 1: Password Resets, Week 2: Remote Job Scams)
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ 2. Prompt Execution │  Run standardized templates from AI_PROMPT_LIBRARY.md in
│    & Draft Creation │  local or web-based AI assistant (e.g., Google AI Studio)
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ 3. Fact-Checking &  │  Security analyst reviews draft for:
│    Human Review     │  - Accurate guidance (e.g., check domain, don't trust padlock)
│                     │  - Appropriate tone (supportive, educational, no victim blaming)
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ 4. Staging into Kit │  Analyst appends verified entries into:
│    Data Files       │  - data/social_campaign.json
│                     │  - data/quiz_questions.json
└──────────┬──────────┘
           │
           ▼
┌─────────────────────┐
│ 5. Campus Broadcast │  Communications team schedules posts on social feeds and
│                     │  incorporates new questions into student portal quizzes
└─────────────────────┘
```

### Step-by-Step Execution Guide

1. **Topic Identification (Monday):** Review recent campus helpdesk tickets or CISA advisories to identify the week's focal theme (e.g., Smishing & Delivery Text Scams).
2. **Draft Generation (Tuesday):** Execute Prompt Template #3 (Social Media Post) and Prompt Template #2 (Quiz Authoring) from `docs/AI_PROMPT_LIBRARY.md`.
3. **Verification Checklist (Wednesday):**
   - [ ] Does the advice match NIST and CISA security recommendations?
   - [ ] Are all referenced URLs strictly reserved example domains (`.test`, `example.edu`)?
   - [ ] Is the language free of technical jargon, making it accessible to non-technical students?
   - [ ] Is the visual concept feasible for student graphic designers?
4. **Data Staging (Thursday):** Paste the JSON-formatted post into `data/social_campaign.json` and the corresponding question into `data/quiz_questions.json`.
5. **Distribution (Friday):** Deploy content across student organization channels, campus digital signage, and social media.

## 3. Optional Automated Pipeline (Zapier / Make Architecture)

For institutions seeking to streamline the drafting phase across multiple campuses, an automated pipeline can be constructed using Zapier or Make (Integromat) free tiers.

### Architectural Diagram

```
+-----------------------------------------------------------------------------------+
|                        STEP 1: THREAT FEED INGESTION                              |
|   Trigger: RSS Feed Watcher (CISA Alerts, CERT-In Bulletins, or Campus Ticket Log)|
|   - Frequency: Weekly polling / New item trigger                                  |
+-----------------------------------------------------------------------------------+
                                         │
                                         ▼ (Payload: Title, Summary, CVE/Tactic)
+-----------------------------------------------------------------------------------+
|                     STEP 2: CONTENT TRANSFORMATION & DRAFTING                     |
|   Action: Webhook to LLM API (Google Gemini 1.5 Flash / OpenAI GPT-4o-mini)       |
|   - System Prompt: Enforces collegiate educational tone, JSON output format,      |
|     defensive boundaries, and anti-hallucination constraints.                     |
+-----------------------------------------------------------------------------------+
                                         │
                                         ▼ (Structured JSON Draft)
+-----------------------------------------------------------------------------------+
|                   STEP 3: MANDATORY SAFETY REVIEW STAGING GATE                    |
|   Action: Create Row in "Staging & Review Queue" (Google Sheets / Notion / Airtable)|
|   - Columns: Topic, Draft Headline, Draft Message, Quiz Question, Status          |
|   - Default Status: "PENDING HUMAN REVIEW"                                        |
|   - [SAFETY CRITICAL]: PIPELINE HALTS HERE UNTIL MANUAL SIGN-OFF                  |
+-----------------------------------------------------------------------------------+
                                         │
                                         ▼ (Human Analyst Toggles Status to "APPROVED")
+-----------------------------------------------------------------------------------+
|                     STEP 4: APPROVED DISPATCH & PUBLISHING                        |
|   Trigger: Row Updated where Status == "APPROVED"                                 |
|   - Action A: Append to production JSON repository / GitHub Pull Request          |
|   - Action B: Draft social post in Hootsuite / Buffer for campus comms queue      |
|   - Action C: Send confirmation alert to Campus InfoSec Slack / Teams Channel     |
+-----------------------------------------------------------------------------------+
```

### Make (Integromat) Scenario Blueprint

- **Module 1 (RSS / Webhook):** Monitor `https://www.cisa.gov/cybersecurity-advisories/all.xml` for student-relevant keyword matches (`phishing`, `credential`, `social engineering`, `student`).
- **Module 2 (HTTP / AI Request):** Sends structured prompt to Gemini API with temperature `0.2` to generate one draft social post and one quiz question formatted in JSON.
- **Module 3 (Google Sheets):** Appends draft with a clickable `Status` dropdown defaulting to `NEEDS_REVIEW`.
- **Module 4 (Router & Guard):** A secondary scenario triggers *only* when `Status` is manually updated to `APPROVED`. If status is anything else, the scenario terminates immediately.

## 4. Verification & Content Quality Guardrails

Every automated draft must pass this verification protocol prior to approval:

| Verification Dimension | Checkpoint | Failure Action |
|---|---|---|
| **Domain Safety** | Ensure zero live commercial domains or actual university names are referenced. | Replace with RFC 2606 reserved domains (`example.edu`, `portal.example.test`). |
| **Technical Accuracy** | Verify that security recommendations align with CISA guidelines (e.g. avoiding advice that recommends replying to spam). | Rewrite guidance to specify out-of-band contact or official reporting. |
| **Tone & Empathy** | Ensure messaging does not shame victims or use punitive language. | Adjust phrasing to emphasize supportive campus defense and collective vigilance. |
| **Plausibility & Context** | Confirm that scenarios reflect realistic college contexts (financial aid, registration, internships). | Discard abstract corporate enterprise scenarios. |

## 5. Summary & Implementation Recommendation

For a college capstone demonstration, the **Manual Workflow** is recommended as the primary operational demonstration, as it proves deep understanding of the editorial and security review process without requiring cloud service setup or API fees. The Zapier/Make pipeline can be presented during slide 5 of the presentation to demonstrate enterprise scalability.
